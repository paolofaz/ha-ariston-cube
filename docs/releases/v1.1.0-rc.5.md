# Ariston Cube 1.1.0-rc.5 — fix Cube S add/remove and editor re-use

**Experimental editor prerelease — not part of stable 1.0.1 or the gas Energy-hour rc.2 branch.**

## Fix for "Unknown zone metadata; do not write a partial source"

In rc.4 the new add/remove handler rejected real `ChZn1` responses
containing **additional zone-level fields**. It returned this error during
the **pre-POST validation**, so the rejected attempt never modified the
Cube S schedule.

The rc.5 handler now accepts the same extra zone-level read fields that
the rc.3 *working move-boundary code* already accepted. It uses exactly
the same **`{"plans": [...]}` POST format** used by that field-tested
implementation, instead of adding unknown metadata to an unverified
write request.

It still:
- fingerprints the **complete original `ChZn1` response**, including
  additional fields; if Ariston or the official app changes it since
  preview, the write is refused;
- rejects unknown metadata *inside* a plan or a slice, which could
  otherwise be lost during an edit;
- reads the program immediately before the edit, sends **one POST
  only**, and checks the exact Comfort/Economy schedule on all seven
  weekdays with a new GET. No automatic retry on ambiguous outcomes.

## Editor improvement

After a **successfully cloud-verified save**, the editor remains open
and ready for another operation. A consumed preview/fingerprint cannot
be reused: **every further save requires a fresh Anteprima and explicit
confirmation**. If the cloud result is ambiguous, editing stays blocked
in the current session.

An explicitly identified **pre-POST validation refusal** now displays
"Nessuna modifica inviata" and allows another preview without closing
and reopening the card.

Wait for the updated day to appear in the timeline before choosing a
follow-up edit; the cloud is read fresh on every preview.

## How to field-test add/remove

1. Save a screenshot of the complete current week in the official
   Ariston app. Confirm you are using **rc.5**, not rc.4.
2. On the existing weekly card choose **Modifica fasce → Aggiungi fascia**,
   choose a day and a *non-existing* boundary/start time and its
   Comfort/Economy preset. Select **Anteprima**, inspect before/after,
   then explicitly confirm a **single save**.
3. Verify the full weekday in the official Ariston app.
4. After the card updates, choose **Elimina fascia**, select that newly
   added time, preview and confirm a **new, separate write**. Verify
   that the original program has returned, including adjacent days.

The POST format is grounded in the field-tested rc.3 move command,
but **add/remove have not yet been independently field-verified**.
A refused or ambiguous write must never be repeated blindly.

## No interaction with Energy gas sensors

This RC remains based only on the weekly editor branch. It does NOT
contain the gas statistics-hour correction in `v1.0.2-rc.2`. Reverting
to the gas branch will not undo previously written Cube S schedule
changes: verify the *original schedule* before switching back.

The stable `main` branch, gas ledger, cumulative gas sensor IDs,
Recorder database and the old prerelease tags are untouched.
