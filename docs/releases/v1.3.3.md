# v1.3.3 — Shared HTTP 429 adaptive backoff

Maintenance release to reduce unnecessary requests when the Ariston NET
cloud applies rate limiting. This is an **unofficial community integration**;
the cloud API remains subject to change or restrictions.

## Changes

- Preserve the regular **60-second** main polling interval when the cloud is
  responsive.
- When any mobile API or R2 web portal request receives **HTTP 429**, suspend
  further requests from **both clients** for a local shared cooldown.
- Escalate on repeated 429 responses: **5 → 10 → 20 → 40 → 60 minutes**,
  capped at 60 minutes for the client policy, and honor a longer valid server
  **Retry-After** delay (seconds or HTTP date).
- Once a successful request completes **after** cooldown, reset the escalation.
  Concurrent, already-in-flight successful requests cannot accidentally
  cancel the suspension.
- Do **not** sleep, queue, or automatically retry writes. Previously sent
  commands are never replayed. No auth secrets or cloud response contents
  are exposed in throttle errors.
- Keep the existing **two-hour pause on web login HTTP 403** separate from
  the new shared HTTP 429 handling.
- Align integration metadata and diagnostics with **1.3.3** and add offline
  coverage for shared mobile/web blocking, server hints, recovery, and
  single-shot command behavior.

## Impact and installation

Normal operation, entity IDs, local weekly schedules, gas cumulative meters,
and Recorder persistence are unchanged. During cloud rate limiting, data may
become temporarily stale and user commands fail fast until the cooldown
expires. The integration automatically resumes normal scheduled reads; it does
not retroactively fetch missed gas/energy windows.

Update through HACS and **restart Home Assistant**. Do not remove the
integration, .storage, or Recorder history.

The v1.3.0 weekly Lovelace card JavaScript has not changed; its optional
resource cache-busting suffix may remain \`?v=1.3.0\`.

## Testing

Offline Python tests cover exponential cooldown, Retry-After, HTTP 429 from
both API clients and login stages, no queued/retried write, and recovery.
CI also runs the JavaScript editor tests, HACS validation, and hassfest.
No new physical-boiler test is claimed for this change.
