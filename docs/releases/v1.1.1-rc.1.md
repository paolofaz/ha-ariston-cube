# Ariston Cube v1.1.1-rc.1 — gas Energy-hour alignment on stable 1.1.0

**Experimental pre-release** based directly on **stable v1.1.0** (the full
Cube S schedule editor, including multi-day **Clona giorno**). Adds the
previously field-tested **manual** gas-hour preview, apply and inspect actions
from gas experiment **v1.0.2-rc.2**.

## What changes

Ariston cloud reports a complete **two-hour Smc bucket** after the interval.
For example, a 12:00–14:00 Ariston bucket published around 14:10 enters
Home Assistant statistics for 14:00–15:00. With the user-triggered
correction **after 15:15**, its entire increment is moved into 13:00–14:00
and removed from 14:00–15:00. The total cumulative sensor reading and
all later hourly sums are unchanged.

This version supports **only manual, guarded correction**. It does NOT
run an automation or modify every subsequent period automatically.

- Keep the **same two cumulative Smc sensors**, exact entity IDs and
  unique IDs, and **the original persistent gas ledger and offsets**.
- Never reset source sensors or delete HA Recorder history/statistics.
- Preview reads a real Ariston two-hour ledger bucket and both existing
  Recorder hourly rows, checking their sum and state delta.
- Apply requires the fingerprint returned by a fresh preview and
  `confirm: true`. It imports at most one corrected hourly row per
  sensor using Home Assistant's Recorder statistics API.
- The existing delayed-Recorder verification fix checks up to **12 times
  via READS ONLY**, never automatically importing twice.
- Previously corrected periods are not touched: only the latest closed
  eligible Ariston two-hour bucket is considered; DST and inconsistent
  ledger/statistics data are refused.
- An additional **read-only inspection** action can display completed
  hourly sums for both gas sensors (last 72 hours).

## How to test the 12:00–14:00 Ariston bucket on 2026-10-28

1. Back up Home Assistant Recorder before the very first correction.
2. Upgrade to **v1.1.1-rc.1** in HACS and restart Home Assistant.
   All Cube S editor functionality from stable v1.1.0 is retained.
3. Check that Ariston has delivered the 12:00–14:00 gas bucket (~14:10).
4. **At or after 15:15 Europe/Rome**, run the READ-ONLY preview in
   Home Assistant **Developer Tools → Actions**:

   ```yaml
   action: ariston_cube.preview_energy_hour_alignment
   ```

5. Inspect the returned `local_bucket`, `target_start`,
   `following_start`, and both sensor operations. For this date,
   the expected **target statistics hour is 13:00–14:00 local
   (UTC start 2026-10-28T12:00:00+00:00)** and the following hour
   is 14:00–15:00 (UTC start 13:00). The preview should identify
   bucket `2026-10-28 12:00–14:00` with `can_shift` for at least
   one sensor if gas was consumed. A zero bucket stays unchanged.
6. **Do not run apply until the preview is examined**. To make the
   one-time correction, use the fresh, full 64-character fingerprint:

   ```yaml
   action: ariston_cube.apply_energy_hour_alignment
   data:
     fingerprint: "PASTE_THE_EXACT_PREVIEW_FINGERPRINT"
     confirm: true
   ```

7. To verify actual Recorder statistics without writing, after the
   target and adjacent hours are available:

   ```yaml
   action: ariston_cube.inspect_energy_hour_alignment
   data:
     target_start: "2026-10-28T12:00:00+00:00"
   ```

   Each sensor's `consumption_in_target_hour` should show its actual
   Ariston 12:00–14:00 bucket, while
   `consumption_in_following_hour` should be approximately zero.

If apply reports an unconfirmed result **DO NOT retry**: the import
might have succeeded, as happened in the first field test. Use the
read-only inspect action to verify the real Recorder sums first.

## Version isolation

This branch is based on stable 1.1.0, not on the older gas RC's
1.0.1 base. Stable `main`, the immutable 1.1.0 release and the
previous gas experiments are untouched. Weekly schedule writes and
gas Energy-hour statistics correction remain independent, opt-in
operations. **No new gas sensors are created.**
