# v1.4.0 — Temporary Manual Heating

Adds a third option, **Manuale temporaneo**, to the existing **Modalità riscaldamento** select. This is a local Home Assistant override: Ariston still receives the already-supported manual `ZoneMode=2` command and later AUTO `ZoneMode=3`.

## Behavior

- Activate temporary Manual: read the original Cube S weekly schedule freshly, find the next **real** Comfort/Economy change, and send the existing guarded Manual command.
- At that scheduled time, request AUTO using the normal validated command path.
- Ignore redundant weekly programme boundaries that repeat the same preset.
- Save the scheduled expiry in HA `.storage`, restore it after HA restarts, and expose `ariston_ritorno_auto_previsto` on the select.
- If the user explicitly chooses normal AUTO or Manuale, cancel the outstanding timer.
- When the weekly schedule coordinator refreshes a changed timetable, recompute the next deadline from the original override start.
- If the return write is not cloud-confirmed, never automatically replay it after timeout or a reboot. The select exposes `ariston_manuale_temporaneo_esito`; check Ariston NET and use AUTO explicitly to recover.

## Safety and compatibility

This release does **not** alter the Cube S weekly programme, existing entity unique IDs, gas Smc ledgers, Recorder, Energy alignment, mobile/web authentication, or cloud rate-limiting rules. Manuale temporaneo requires a complete seven-day programme and the existing winter/heating capabilities. It does not issue a boiler command if the programme is missing or malformed.

The automatic return depends on Home Assistant being active and Ariston NET being reachable. A missed return during downtime is attempted at startup only if no previous attempt was persisted. An ambiguous attempted command is not repeated.

## Upgrade

Update from HACS and restart Home Assistant. Do not remove/re-add the integration, delete `.storage`, or reset Recorder. The existing select retains its unique ID and gains one option.

## Verification

Offline regression tests cover real boundaries, redundant slices, week wrap, missing schedule, activation/expiry, explicit cancellation, restart/no duplicate write and schedule refresh. The release workflow runs the existing Python and JavaScript suites plus hassfest before publishing. Physical boiler validation remains to be performed.
