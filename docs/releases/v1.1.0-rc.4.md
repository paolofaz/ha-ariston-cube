# Ariston Cube 1.1.0-rc.4 — Cube S weekly band editor

**Experimental prerelease; not the stable 1.0.1.**

This build extends the validated **rc.3 move-boundary editor** to support
**adding and removing one Comfort/Economy boundary per operation** within
the existing `ariston-cube-weekly-card` Lovelace card.

### User interface

Open your existing Cube S weekly card, select **Modifica fasce**, then a
weekday. On this version the **Operazione** dropdown offers:

- **Sposta orario:** move an existing change of preset (already tested with
  the Ariston app in rc.3).
- **Aggiungi fascia:** choose new starting time and either Comfort or Economy.
  The chosen preset applies from that time to the following existing boundary.
- **Elimina fascia:** choose an existing boundary. The preceding setting
  continues until the next boundary.

For all three, select **Anteprima** before **Salva sul Cube S**. The
confirmation dialog compares the selected day before and after. Saving
changes the **real** Ariston cloud schedule and **cannot be undone** by
reinstalling stable software.

### Safety

- A full-week **fresh GET** and fingerprint are checked before building the
  cloud request, to reject changes made by phone/another client since preview.
- **One POST only**, **one full seven-day readback**. Never automatically
  retry an ambiguous or failed write.
- When a day shares a plan with other weekdays, split out only the selected
  day and verify that the other six days are unchanged.
- Reject adding at an existing time, an identical active preset, malformed
  times, unknown presets, excess 48 slices, incomplete source weekdays,
  source metadata that would be lost, and **removing/moving the midnight
  boundary**.
- Changes to the gas cumulative sensors, Energy/Recorder statistics,
  persistent gas ledger and offsets are **not part of this branch**.

### Alternative Developer Tools actions

`ariston_cube.preview_weekly_change` is read-only and returns the preview
and `source_fingerprint`; `ariston_cube.write_weekly_change` requires
exactly the same edit plus `expected_fingerprint` and `confirm: true`.

Example *read-only* preview (add a new Economy boundary at 12:00 on Monday):

```yaml
action: ariston_cube.preview_weekly_change
data:
  day: 1
  operation: add
  to_time: "12:00"
  preset: Economy
```

Do **not** save this example blindly to a real boiler: choose intended
timings and inspect before/after carefully, including the official Ariston
app after the first actual write.

### Test status

Offline Python and JavaScript regression tests validate all operations and
one-POST/readback semantics. **Adding/removing boundaries has not yet been
field-verified on the real Ariston Cube S**; only moving a boundary was
confirmed in the official app in rc.3. This build is for a deliberate,
explicit user test, not automatic scheduling.

### Important: separate from the gas attribution test

This prerelease is based on the weekly editor rc.3 branch, NOT on the
separate Energy gas-hour rc.2 branch. Installing either over the other
replaces that branch's experimental feature. **Finish the gas-hour trial
before installing rc.4**. Stable `main` remains unchanged.
