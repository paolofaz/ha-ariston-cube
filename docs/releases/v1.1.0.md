# Ariston Cube 1.1.0 — Stable Cube S weekly schedule editor

Stable release from the field-tested 1.1.0-rc.3 through rc.6 weekly
editor series, plus a guarded **multi-target clone weekday** action.

## What the editor does

The Home Assistant Cube S weekly Lovelace timeline can now edit the real
Comfort/Economy programme:

1. **Sposta orario**: move an existing preset boundary to a 15-minute time.
2. **Aggiungi fascia**: define BOTH start and end, at 15-minute increments;
   automatically resume the original preset at the end. Reject conflicting
   boundaries and overlapping edits.
3. **Elimina fascia**: remove an existing boundary. When the adjacent
   restoration boundary is redundant, remove it too.
4. **Clona giorno**: select one source weekday and **multiple destination
   weekdays** with checkboxes. For example, choose Monday and Wednesday,
   Friday and Sunday; the preview shows the complete source programme and
   before/after for each target. Exactly ONE cloud POST updates all changed
   targets, not a sequence of per-day writes.

All actions require a **read-only preview** from a fresh cloud GET,
a full-zone fingerprint, an explicit confirmation dialog, ONE schedule
POST, and an exact seven-day cloud GET/readback. A stale fingerprint
blocks the write. Ambiguous cloud responses **are never retried**.

The confirmation dialog now focuses on the requested before/after
change; the old unnecessary sentence about reverting to stable has
been removed.

On confirmed saves, the same editor stays open for another fresh
preview. On ambiguous writes it blocks more writes until the programme
is verified with the official Ariston app.

## Clone example: Monday -> Wednesday, Friday, Sunday

Read-only preview via Developer Tools / Actions:

```yaml
action: ariston_cube.preview_weekly_clone
data:
  source_day: 1
  destinations: [3, 5, 0]
```

The action returns before/after schedules, the changed target weekdays,
and `source_fingerprint`, without any cloud write. Only a separate
`ariston_cube.clone_weekly_days` call with identical source and targets,
`expected_fingerprint` and `confirm: true` can write. Normally use
the Lovelace card instead of Developer Tools.

## Release safety and compatibility

- The source, unselected weekdays and unrelated boiler controls are
  preserved. The clone writer refuses invalid/duplicate/self-selected
  targets, missing weekdays, unknown plan/slice metadata, and stale
  fingerprints.
- The existing gas cumulative sensor entity IDs, their unique IDs,
  the gas ledger and offsets, and historical Energy Recorder data are
  not modified by this release. A normal HACS update does **not**
  require recreating the gas sensors or clearing statistics.
- **The separate experimental gas-hour alignment v1.0.2-rc.2 is not
  included in v1.1.0**; it is still isolated in its own branch.
  Installing this stable release while using gas rc.2 replaces that
  experimental hour-shift functionality, but not existing gas sensor
  history or prior hourly statistics corrections.
- Old stable **v1.0.1** remains available as its original Git tag/release.
- Confirm the boiler's current timetable using the official Ariston
  app, especially if previous experiments left changes in effect.
  Reinstalling an old version does not undo cloud schedule changes.
- Earlier **move**, **add**, and **remove** operations were field-tested
  on the real Cube S. The new **multi-destination clone** has extensive
  offline and simulated cloud-contract tests; it still needs the
  first deliberate live-device verification before it can be described
  as field-tested.
- CI includes Python test coverage for the gas ledger, entities, cloud
  parsing, calendar and week edits, plus JavaScript behavior tests for
  the editor and multi-select clone.

This is an independent community project; cloud API behavior may change.
