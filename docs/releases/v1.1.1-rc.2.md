# Ariston Cube v1.1.1-rc.2 — Automatic gas Energy-hour alignment

**Experimental automatic RC, based on stable v1.1.0 and the successfully
field-tested manual gas correction v1.1.1-rc.1.** Stable `main` and its
existing v1.1.0 release are NOT changed.

## What now happens automatically

Every TWO HOURS, at **:15 of each ODD local hour** (01:15, 03:15,
05:15, 07:15, 09:15, 11:15, 13:15, 15:15, 17:15, 19:15, 21:15, 23:15),
Home Assistant starts a single safeguarded check.

Example: when Ariston reports the 14:00–16:00 Smc bucket at about 16:10
(or on the 16:40 backup), the cumulative gas sensor increments in the
16:00–17:00 hour. **At 17:15**, after the hourly Recorder window closes,
this release can reattribute that increment to **15:00–16:00**, exactly
like the manual tests for 06:00–08:00 and 12:00–14:00.

The automatic component **reuses the unchanged, already field-tested
preview/plan/apply implementation**. It first validates both existing gas
sensors, the exact two-hour cloud bucket, the complete current Recorder
hourly rows and a fingerprint. Only `can_shift` rows are eligible.
A second fresh plan and fingerprint check happens immediately before
the real import. It uses the Home Assistant statistics API to update
the one eligible hourly row per sensor, followed by the same delayed
read-only verification (up to 12 checks). No automatic import is
repeated, even on ambiguous outcomes.

- **No modifications** to the two cumulative gas sensor IDs/unique IDs,
  existing entity states, gas ledger, gas offsets, SQLite database,
  or other hours' Recorder statistics.
- **No catch-up** of missed times during downtime; this RC only handles
  the scheduled current two-hour window.
- **No retry**, including when Ariston data or compiled hourly stats
  are missing, or a write/readback is ambiguous.
- No writes in even hours, before :15, or across unsupported DST
  transitions.
- The entire stable v1.1.0 **Cube S weekly editor**, including
  **Clona giorno** to multiple target weekdays, remains included.
- The manual `preview_energy_hour_alignment`,
  `apply_energy_hour_alignment`, and
  `inspect_energy_hour_alignment` services are preserved.

## Install and verify this evening

1. In HACS switch to pre-release **v1.1.1-rc.2**, restart Home Assistant.
   The automatic schedule is **enabled by default** in this RC.
2. You do NOT have to run manual apply. After each odd hour :15
   (e.g. 17:15, 19:15, 21:15), run the following **READ-ONLY**
   Home Assistant Developer Tools → Actions command:

   ```yaml
   action: ariston_cube.inspect_automatic_energy_hour_alignment
   ```

   Its `recent_attempts` list (last eight cycles, in memory only)
   includes `target_start`, `local_bucket`, and one of:
   - `verified_hourly_import`: automatically corrected and verified;
   - `no_change_needed`: zero consumption or already correctly attributed;
   - `skipped_safety_check` / `skipped_error`: no write attempted;
   - `unconfirmed_do_not_retry`: an import may have been sent;
     **never manually or automatically reapply blindly**. Inspect
     the Recorder sums with the next read-only service instead.

3. Independently verify a completed hour using the existing read-only
   `ariston_cube.inspect_energy_hour_alignment` action:

   ```yaml
   action: ariston_cube.inspect_energy_hour_alignment
   data:
     target_start: "2026-10-28T14:00:00+00:00"
   ```

   This UTC target is **15:00–16:00 local Italy on 2026-10-28**,
   the second hour of the 14–16 Ariston consumption bucket.
   For the 16–18 Ariston bucket corrected at 19:15, use
   `2026-10-28T16:00:00+00:00` (17–18 local).
   After a successful correction, the following local hour has
   zero consumption while the correct target hour contains the
   real bucket consumption. If the bucket is genuinely zero,
   both hourly consumption readings should remain zero.

In the evening, verify 2–3 periods using these read-only actions.
If those tests are successful, the next step is a **stable v1.2.0
merge into main**, separately from this prerelease; no merge
or overnight monitoring happens automatically outside Home Assistant.

**Home Assistant restart resets in-memory automatic-run diagnostics**,
but it does not reset the gas statistics, ledger or physical schedule.
A restart between scheduled hours will not retroactively shift a
missed period. The existing cloud/Recorder consistency checks reject
already-aligned periods.

## Important caution

This is the first automatic statistics-writing build, so keep a
Home Assistant Recorder backup. Do not manually run
`apply_energy_hour_alignment` on the same period while the automatic
scheduler is active. If any cycle is unconfirmed, use ONLY the read-only
inspection action and report the result before further action.
